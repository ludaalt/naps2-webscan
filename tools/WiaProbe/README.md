# WiaProbe — консольный пробник WIA

Утилита для диагностики сканеров, которые не сканируют через службу NAPS2.WebScan.
Сканирует **тем же кодом, что и служба**: `NAPS2.Sdk` 1.1.6, `NAPS2.Wia` 2.0.3,
`net8.0-windows`, `x64`. Поэтому поведение драйвера совпадает, а результат
пробника можно сравнивать с результатом службы.

## Зачем

Служба при ошибке сканирования показывает только общий текст. Пробник показывает:

- какие WIA-устройства вообще видны (в WIA 2.0 и в WIA 1.0);
- какие свойства, размеры и разрешения объявляет драйвер;
- какая рамка `XEXTENT/YEXTENT` реально уходит драйверу для A4 и Letter;
- какая комбинация настроек падает и с каким `HRESULT`;
- полную цепочку исключений (`ScanDriverUnknownException -> WiaException`).

Типичный вопрос, на который отвечает пробник: «дело в размере страницы,
в разрешении, в глубине цвета, в версии WIA или драйвер не работает вовсе».

## Сборка

Из корня репозитория службы:

```powershell
dotnet build .\tools\WiaProbe
```

Запуск во время разработки:

```powershell
dotnet run --project .\tools\WiaProbe -- list
```

## Сборка для ПК без .NET 8

Собирается **один exe**, без DLL рядом: среда выполнения .NET и все зависимости
внутри, устанавливать .NET на проблемный ПК не нужно.

```powershell
dotnet publish .\tools\WiaProbe\WiaProbe.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:DebugType=None -p:DebugSymbols=false -o .\tools\WiaProbe\publish
```

Результат — `tools\WiaProbe\publish\WiaProbe.exe` (около 36 МБ). Скопировать
этот файл на проблемный ПК можно любым способом: флешка, сетевая папка, почта.
Рядом ничего не нужно, запускать можно из любой папки.

- `-p:EnableCompressionInSingleFile=true` уменьшает файл примерно вдвое;
- `-p:DebugType=None` убирает `WiaProbe.pdb`;
- папка `publish` исключена в `.gitignore`, в установщик службы не попадает
  (там используется только `publish\*` из корня репозитория).

Проверка на этом ПК: один файл, запуск из пустой папки, старт около 2 секунд.

Запускать **от обычного пользователя**, а не от администратора: служба работает
под `LocalSystem`, и разница в правах — одна из проверяемых версий.

Если драйвер сканера строго 32-битный, нужна сборка `win-x86`:

```powershell
dotnet publish .\tools\WiaProbe\WiaProbe.csproj -c Release -r win-x86 --self-contained true -p:PublishSingleFile=true -p:PlatformTarget=x86 -o .\tools\WiaProbe\publish-x86
```

Для неё нужен пакет `Microsoft.NETCore.App.Runtime.win-x86` — при первой сборке
он скачивается из NuGet, то есть нужен интернет. Для диагностики службы это
редкий случай: служба 64-битная, и драйвер в ней тоже работает в 64-битном
процессе.

## Команды

Запуск двойным кликом (без аргументов) равен `WiaProbe.exe list`: пробник
показывает видимые устройства и ждёт Enter, чтобы окно не закрылось. Остальные
команды удобнее запускать из PowerShell, открытого в папке с exe.

Чтобы сохранить вывод для пересылки:

```powershell
.\WiaProbe.exe dump --device Kyocera --size a4,letter --dpi 200,300 2>&1 | Out-File -Encoding utf8 dump.txt
```

### `list`

Перечисляет WIA-устройства так же, как это делает служба.

```powershell
WiaProbe.exe list
WiaProbe.exe list --wia both
```

`--wia 1` — только WIA 1.0, `--wia both` — WIA 2.0 и WIA 1.0 подряд.

### `dump`

Печатает свойства устройства и его item'ов и считает рамку для каждого размера.

```powershell
WiaProbe.exe dump --device Kyocera --size a4,letter --dpi 200,300
```

Что смотреть в выводе:

- `IPS_MAX_HORIZONTAL_SIZE` / `IPS_MAX_VERTICAL_SIZE` (WIA 2.0) или
  `DPS_HORIZONTAL_BED_SIZE` / `DPS_VERTICAL_BED_SIZE` (WIA 1.0) — паспортный
  размер области сканирования в 1/1000 дюйма;
- `min` / `max` / `step` / `values` у `IPS_XRES` — какие разрешения принимает
  драйвер;
- `values` у `IPA_DATATYPE` — поддерживаемые глубины цвета (`0` — ч/б,
  `2` — серый, `3` — цвет);
- строки `XEXTENT` / `YEXTENT` — что уйдёт драйверу. Если ширина A4 больше
  максимума, в строке будет пометка «ширина обрезана».

Если свойства максимального размера нет, пробник пишет предупреждение:
`NAPS2.Sdk` 1.1.6 в этом случае падает с `KeyNotFoundException` ещё до передачи
изображения. Это отдельная причина, не `80004005`.

### `scan`

Прогоняет матрицу сканирований и сохраняет страницы в PNG.

```powershell
WiaProbe.exe scan --device Kyocera --size a4,letter --dpi 200 --depth color
WiaProbe.exe scan --device Kyocera --wia both --size a4,letter --dpi 200,300 --depth color,gray,bw --verbose
```

Ключи:

| Ключ          | Значение по умолчанию | Назначение                                |
| ------------- | --------------------- | ----------------------------------------- |
| `--device`    | первое устройство     | фильтр по части имени или ID              |
| `--wia`       | `2`                   | версии WIA: `2`, `1`, `both`              |
| `--size`      | `a4,letter`           | размеры страницы: `a4`, `letter`, `legal` |
| `--dpi`       | `200`                 | разрешения                                |
| `--depth`     | `color`               | глубины цвета: `color`, `gray`, `bw`      |
| `--out`       | `.\wiaprobe-out`      | папка для страниц                         |
| `--delay`     | `2000`                | пауза между сканированиями, мс            |
| `--timeout`   | `120`                 | таймаут одного сканирования, с            |
| `--native-ui` | выключено             | родной диалог драйвера                    |
| `--verbose`   | выключено             | отладочный журнал NAPS2                   |

Один сканер — одна страница за проход. Пауза между запусками нужна, чтобы
устройство успело закрыть задание: без неё следующий запуск часто получает
«занято» и ошибку, не связанную с тестом.

## Как читать результат

Пример строк:

```text
OK   страница 1: 412 КБ, 1654x2338 px, 3.1 с -> 01-wia2.0-a4-200-color-p1.png
FAIL ScanDriverUnknownException: ... <- WiaException: WIA error code 80004005 [0x80004005 E_FAIL — общий отказ драйвера]
```

Выводы:

- `a4` работает, `letter` падает — причина в размере страницы, лечится
  настройкой `ScanRegions` на стороне клиента eSCL;
- `letter` работает, `a4` падает — драйвер не принимает A4, нужен размер
  из его паспортных возможностей;
- падают все размеры на 200 dpi, но работают на 300 dpi — причина в разрешении;
- падает только `color`, а `gray` и `bw` работают — причина в глубине цвета;
- падает только WIA 2.0, а WIA 1.0 работает — драйвер кривой в WIA 2.0;
- падают все комбинации с одним и тем же `E_FAIL` — размер страницы ни при чём,
  отказ приходит из `Download`, то есть из самого драйвера или устройства.

`E_FAIL` (`0x80004005`) в NAPS2 означает, что свойства задались, а передача
изображения не удалась. Это не «неверный размер страницы»: такой отказ выглядел
бы как `E_INVALIDARG` (`0x80070057`) или как ошибка установки свойства в журнале
`--verbose`.

Если в пробнике всё работает, а через службу нет — разница в контексте запуска:
служба работает под `LocalSystem` в сессии 0, без интерактивного рабочего стола.
В этом случае стоит проверить скан через пробник, запущенный от имени `LocalSystem`
(например, `psexec -s -i`), и сравнить журналы.

## Ограничения

- WIA на Windows не поддерживает сканирование из сессии службы так же надёжно,
  как из интерактивной сессии: часть драйверов требует рабочий стол.
- Пробник не заменяет журнал службы: журнал NAPS2 при `--verbose` идёт в консоль,
  а не в файл.
- Пробник не проверяет eSCL-путь службы. Для этого есть `tools/scan-escl.ps1`.
