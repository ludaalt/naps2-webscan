# WiaProbe — консольный пробник WIA

Утилита для диагностики сканеров, которые не сканируют через службу NAPS2.WebScan.
Сканирует **тем же кодом, что и служба**: `NAPS2.Sdk` 1.1.6, `NAPS2.Wia` 2.0.3,
`net8.0-windows`, `x64`. Поэтому поведение драйвера совпадает, а результат
пробника можно сравнивать с результатом службы.

## Зачем

Служба при ошибке сканирования показывает только общий текст. Пробник показывает:

- какие WIA-устройства вообще видны (в WIA 2.0 и в WIA 1.0);
- какие свойства, размеры и разрешения объявляет драйвер;
- какая рамка `XEXTENT/YEXTENT` реально уходит драйверу для A4 и Letter;
- какая комбинация настроек падает и с каким `HRESULT`;
- полную цепочку исключений (`ScanDriverUnknownException -> WiaException`);
- контекст: под какой учётной записью идёт скан, запущены ли службы,
  что Windows думает об устройстве, что служба раздаёт в браузер и что
  уже записано в её журнале.

Типичный вопрос, на который отвечает пробник: «дело в размере страницы,
в разрешении, в глубине цвета, в версии WIA, в службе или драйвер не работает
вовсе».

## Версия

Первая строка консоли и отчёта — версия с датой сборки:

```text
WiaProbe 20261117: процесс x64, ОС 10.0.19045.0, пользователь SOGAZ-Med
```

`20261117` — дата сборки exe (ГГГГММДД), а не дата запуска: по первой строке
сразу видно, какую сборку прислали. Проверить версию, ничего не запуская:

```powershell
.\WiaProbe.exe --version
```

При сборке дату можно задать явно: `-p:BuildDate=20261117`.

## Сборка

Из корня репозитория службы:

```powershell
dotnet build .\tools\WiaProbe
```

Запуск во время разработки:

```powershell
dotnet run --project .\tools\WiaProbe -- list
```

## Сборка для ПК без .NET 8

Собирается **один exe**, без DLL рядом: среда выполнения .NET и все зависимости
внутри, устанавливать .NET на проблемный ПК не нужно.

```powershell
dotnet publish .\tools\WiaProbe\WiaProbe.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:DebugType=None -p:DebugSymbols=false -o .\tools\WiaProbe\publish
```

Результат — `tools\WiaProbe\publish\WiaProbe.exe` (около 38 МБ). Скопировать
этот файл на проблемный ПК можно любым способом: флешка, сетевая папка, почта.
Рядом ничего не нужно, запускать можно из любой папки.

- `-p:EnableCompressionInSingleFile=true` уменьшает файл примерно вдвое;
- `-p:DebugType=None` убирает `WiaProbe.pdb`;
- папка `publish` исключена в `.gitignore`, в установщик службы не попадает
  (там используется только `publish\*` из корня репозитория).

Запускать **от обычного пользователя**, а не от администратора: служба работает
под `LocalSystem`, и разница в правах — одна из проверяемых версий.

Если драйвер сканера строго 32-битный, нужна сборка `win-x86`:

```powershell
dotnet publish .\tools\WiaProbe\WiaProbe.csproj -c Release -r win-x86 --self-contained true -p:PublishSingleFile=true -p:PlatformTarget=x86 -o .\tools\WiaProbe\publish-x86
```

Для неё нужен пакет `Microsoft.NETCore.App.Runtime.win-x86` — при первой сборке
он скачивается из NuGet, то есть нужен интернет. Для диагностики службы это
редкий случай: служба 64-битная, и драйвер в ней тоже работает в 64-битном
процессе.

## Быстрый старт: один отчёт обо всём

```powershell
.\WiaProbe.exe all
```

Команда подряд делает все проверки и складывает их в один файл:

```text
.\wiaprobe-out\wiaprobe-20261117-102549\
    report.txt     ← полный текстовый отчёт в UTF-8, его и пересылать
    wia\           ← страницы, полученные напрямую через WIA
    escl\          ← страницы, полученные через службу (как из браузера)
```

Отчёт создаёт **любая команда**, кроме `help` и `--version`, — в том числе
`list`, `dump`, `scan`, `service`, `escl`. Папка запуска всегда новая
(`wiaprobe-ГГГГММДД-ЧЧММСС`; если такая уже есть — с суффиксом `-2`, `-3`),
старые отчёты не затираются. Если записать
в `--out` нельзя (нет прав, диск только для чтения), отчёт уходит
в `%TEMP%\WiaProbe\wiaprobe-…`, а точный путь печатается в консоли — файл
появится в любом случае.

Запуск без аргументов (двойной клик) равен `WiaProbe.exe all`: пробник делает
полную диагностику, оставляет отчёт и ждёт Enter, чтобы окно не закрылось.

По умолчанию `all` проверяет WIA 2.0 и 1.0, A4, 200 dpi и три глубины цвета
(цвет, серый, ч/б), затем одно сканирование через службу. Это около 6 коротких
запусков плюс один через eSCL. Явно заданные ключи (`--wia`, `--size`, `--dpi`,
`--depth`, `--device`, `--out`) меняют этот набор.

### Когда запускать

| Когда                             | Команда                          | Зачем                                                        |
| --------------------------------- | -------------------------------- | ------------------------------------------------------------ |
| **До** первого воспроизведения    | `WiaProbe.exe all`               | базовый отчёт: видно ли устройство, работает ли скан вообще |
| В момент ошибки в браузере        | `WiaProbe.exe all --no-scan`     | быстрый контекст, устройство не занимается                   |
| После ошибки, устройство свободно | `WiaProbe.exe all`               | сравнить WIA и путь службы, поймать отказ                    |
| Проверить только службу           | `WiaProbe.exe service`           | службы, PnP, `/devices`, eSCL, журнал — без сканов           |
| Проверить только путь браузера    | `WiaProbe.exe escl`              | сканирование через eSCL-раздачу службы                       |
| Нужен только WIA                  | `WiaProbe.exe scan --verbose`    | матрица настроек, без проверок службы                        |

Перед запуском закройте NAPS2, «Факсы и сканирование», программы Kyocera и
другие сканеры: одно устройство не умеет выполнять два задания одновременно.
**Не запускайте `all` во время сканирования из браузера** — оба задания пойдут
на одно устройство, и вы получите ошибку «занято», которой в обычной работе нет.

`--no-scan` можно запускать в любой момент: он не запускает сканирование, поэтому
не конкурирует с браузером за устройство. Чтение свойств драйвера при занятом
устройстве может не сработать — остальные разделы всё равно соберутся.

### Кодировка и «кракозябры»

В Windows PowerShell 5.1 запись `WiaProbe.exe all > dump.txt` перекодирует
UTF-8 в кодовую страницу консоли, и в файле получаются строки вида
`╨┐╤А╨╛╤Ж╨╡╤Б╤Б`. Это не ошибка сканера. Пробник сам создаёт `report.txt`
в UTF-8 с BOM — читайте и пересылайте его, перенаправление `>` не нужно.

Если всё же нужно сохранить вывод в конкретный файл, используйте встроенный ключ:

```powershell
.\WiaProbe.exe scan --verbose --log C:\temp\scan.txt
```

`--log` работает для любой команды: задаёт точный путь отчёта вместо папки
`wiaprobe-…`, пишет тот же текст, что виден в консоли, в UTF-8. Страницы сканов
при этом сохраняются рядом с отчётом, в подпапки `wia\` и `escl\`.

## Команды

Запуск двойным кликом (без аргументов) равен `WiaProbe.exe all`: пробник делает
полную диагностику, создаёт отчёт и ждёт Enter, чтобы окно не закрылось.
Остальные команды удобнее запускать из PowerShell, открытого в папке с exe.

### `--version`

Печатает версию с датой сборки (`WiaProbe 20261117`) и выходит, отчёт не создаёт.

### `all`

Полная диагностика и отчёт. Разделы отчёта:

1. среда (Windows, пользователь, сессия, права);
2. службы `StiSvc`, `NAPS2.WebScan Service`, `RpcSs`;
3. устройства PnP класса Image;
4. ответ службы: `GET /devices` и eSCL `ScannerCapabilities`;
5. список WIA-устройств (2.0 и 1.0);
6. свойства драйвера и расчёт рамки;
7. матрица сканирований через WIA;
8. одно сканирование через службу (eSCL);
9. журнал службы: ошибки WIA, `Error setting property`, `Correcting DPI`;
10. итог: список «+»/«−» и что делать дальше.

### `service`

Только контекст, без сканирования: среда, службы, PnP, `/devices`, eSCL и
журнал. Удобно, когда устройство занято или сканировать сейчас нельзя.

### `escl`

Сканирует через службу так же, как браузер: `POST ScanJobs`, затем
`NextDocument`. Список сканеров берётся из `GET http://localhost:9899/devices`,
если его нет — перебираются порты 9880–9898.

```powershell
WiaProbe.exe escl
WiaProbe.exe escl --size a4 --dpi 300 --depth gray
WiaProbe.exe escl --escl-port 9880 --no-scan
```

В отличие от `scan`, здесь ошибка означает проблему именно в службе или её
eSCL-обвязке, а не в прямом вызове драйвера.

Страницы сохраняются в `escl\` внутри папки запуска, отчёт — `report.txt`
в её корне.

### `list`

Перечисляет WIA-устройства так же, как это делает служба.

```powershell
WiaProbe.exe list
WiaProbe.exe list --wia both
```

`--wia 1` — только WIA 1.0, `--wia both` — WIA 2.0 и WIA 1.0 подряд.

### `dump`

Печатает свойства устройства и его item'ов и считает рамку для каждого размера.

```powershell
WiaProbe.exe dump --device Kyocera --size a4,letter --dpi 200,300
```

Что смотреть в выводе:

- `IPS_MAX_HORIZONTAL_SIZE` / `IPS_MAX_VERTICAL_SIZE` (WIA 2.0) или
  `DPS_HORIZONTAL_BED_SIZE` / `DPS_VERTICAL_BED_SIZE` (WIA 1.0) — паспортный
  размер области сканирования в 1/1000 дюйма;
- `min` / `max` / `step` / `values` у `IPS_XRES` — какие разрешения принимает
  драйвер;
- `values` у `IPA_DATATYPE` — поддерживаемые глубины цвета (`0` — ч/б,
  `2` — серый, `3` — цвет);
- строки `XEXTENT` / `YEXTENT` — что уйдёт драйверу. Если ширина A4 больше
  максимума, в строке будет пометка «ширина обрезана».

Если свойства максимального размера нет, пробник пишет предупреждение:
`NAPS2.Sdk` 1.1.6 в этом случае падает с `KeyNotFoundException` ещё до передачи
изображения. Это отдельная причина, не `80004005`.

### `scan`

Прогоняет матрицу сканирований и сохраняет страницы в PNG.

```powershell
WiaProbe.exe scan --device Kyocera --size a4,letter --dpi 200 --depth color
WiaProbe.exe scan --device Kyocera --wia both --size a4,letter --dpi 200,300 --depth color,gray,bw --verbose
```

Ключи:

| Ключ          | Значение по умолчанию | Назначение                                |
| ------------- | --------------------- | ----------------------------------------- |
| `--device`    | первое устройство     | фильтр по части имени или ID              |
| `--wia`       | `2`                   | версии WIA: `2`, `1`, `both`              |
| `--size`      | `a4,letter`           | размеры страницы: `a4`, `letter`, `legal` |
| `--dpi`       | `200`                 | разрешения                                |
| `--depth`     | `color`               | глубины цвета: `color`, `gray`, `bw`      |
| `--out`       | `.\wiaprobe-out`      | базовая папка; страницы — в `wia\`         |
| `--delay`     | `2000`                | пауза между сканированиями, мс            |
| `--timeout`   | `120`                 | таймаут одного сканирования, с            |
| `--native-ui` | выключено             | родной диалог драйвера                    |
| `--verbose`   | выключено             | отладочный журнал NAPS2                   |

Один сканер — одна страница за проход. Пауза между запусками нужна, чтобы
устройство успело закрыть задание: без неё следующий запуск часто получает
«занято» и ошибку, не связанную с тестом.

Страницы сохраняются в `wia\` внутри папки запуска, отчёт — `report.txt`
в её корне.

## Что должно быть в отчёте `all`

| Раздел                        | Норма                                                             | Признак проблемы                                                        |
| ----------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 1. Среда                      | сессия 1, обычный пользователь, не SYSTEM                          | скан из сессии 0 или под SYSTEM — другой контекст, чем у браузера       |
| 2. Службы                     | `StiSvc` работает; `NAPS2.WebScan Service` работает, `LocalSystem` | служба остановлена или не установлена                                   |
| 3. PnP (класс Image)          | ваше МФУ: `OK`, без «не подключено»                                | `!!` и статус `Error`/`Unknown` у подключённого устройства              |
| 4. Служба и eSCL              | `/devices` HTTP 200; ваш сканер с портом; eSCL HTTP 200              | служба не отвечает, список пуст, порт eSCL не отвечает                  |
| 5. WIA                        | устройство видно в 2.0 (в 1.0 может не быть)                       | «устройств нет» — драйвер, USB или StiSvc                               |
| 6. Свойства драйвера          | есть максимальный размер; в `IPS_XRES` есть 200 и 300              | нет максимального размера; 200/300 отсутствуют                          |
| 7. Сканирование WIA           | все строки `OK`, есть PNG                                          | `FAIL` и `WiaException ... 80004005`                                    |
| 8. Сканирование через службу  | `OK страница 1`, есть файл в `escl\`                               | `FAIL`, `ErrorDetails` с текстом NAPS2                                  |
| 9. Журнал службы              | нет строк `Error setting property` и `WIA error`                   | эти строки есть — драйвер отверг свойство ещё до передачи изображения   |
| 10. Итог                      | все пункты «+»                                                     | любой «−» — смотрите раздел, на который он указывает                    |

Если в разделе 7 все комбинации падают с одним и тем же `E_FAIL`
(`0x80004005`), а раздел 8 тоже без страниц — отказ приходит из драйвера или
устройства, а не из размера страницы. Если раздел 7 успешен, а раздел 8 нет —
дело в контексте службы (`LocalSystem`, сессия 0) или в eSCL-обвязке.

## Как читать результат `scan`

Пример строк:

```text
OK   страница 1: 412 КБ, 1654x2338 px, 3.1 с -> 01-wia2.0-a4-200-color-p1.png
FAIL ScanDriverUnknownException: ... <- WiaException: WIA error code 80004005 [0x80004005 E_FAIL — общий отказ драйвера]
```

Выводы:

- `a4` работает, `letter` падает — причина в размере страницы, лечится
  настройкой `ScanRegions` на стороне клиента eSCL;
- `letter` работает, `a4` падает — драйвер не принимает A4, нужен размер
  из его паспортных возможностей;
- падают все размеры на 200 dpi, но работают на 300 dpi — причина в разрешении;
- падает только `color`, а `gray` и `bw` работают — причина в глубине цвета;
- падает только WIA 2.0, а WIA 1.0 работает — драйвер кривой в WIA 2.0;
- падают все комбинации с одним и тем же `E_FAIL` — размер страницы ни при чём,
  отказ приходит из `Download`, то есть из самого драйвера или устройства.

`E_FAIL` (`0x80004005`) в NAPS2 означает, что свойства задались, а передача
изображения не удалась. Это не «неверный размер страницы»: такой отказ выглядел
бы как `E_INVALIDARG` (`0x80070057`) или как ошибка установки свойства в журнале
`--verbose`.

Если в пробнике всё работает, а через службу нет — разница в контексте запуска:
служба работает под `LocalSystem` в сессии 0, без интерактивного рабочего стола.
В этом случае стоит проверить скан через пробник, запущенный от имени `LocalSystem`
(например, `psexec -s -i`), и сравнить журналы.

## Что прислать для разбора

Достаточно папки `wiaprobe-ГГГГММДД-ЧЧММСС`:

- `report.txt` — обязательно;
- `wia\` и `escl\` — если в них есть PNG, они подтверждают, какой путь сработал;
- отдельно ничего выгружать не нужно: среда, службы, PnP, журнал службы и
  настройки драйвера уже внутри `report.txt`.

## Ограничения

- WIA на Windows не поддерживает сканирование из сессии службы так же надёжно,
  как из интерактивной сессии: часть драйверов требует рабочий стол.
- Пробник не заменяет журнал службы: в отчёт попадают только строки, которые
  служба уже записала в свои файлы (`%ProgramData%\NAPS2 WebScan Local Service\logs`
  и `logs` рядом с exe).
- `dump` показывает паспортные возможности драйвера, но не гарантирует, что
  конкретная комбинация сработает: это проверяет `scan`.
